# הרשימה שלנו 🛒

רשימת קניות משותפת ליוסף ואגם — מחולקת לפי קטגוריות, מסונכרנת בזמן אמת, עם תקציב משוער, היסטוריה וסטטיסטיקה.

## מה יש באפליקציה

- **רשימה משותפת בזמן אמת** מחולקת ל-13 קטגוריות, מסונכרנת בין שני המכשירים דרך Firestore.
- **סדר קטגוריות לפי מעבר בסופר** — חצי ▲▼ ליד כל קטגוריה מזיזים אותה למעלה/למטה, והסדר נשמר משותף לשניכם.
- **פריטים מהירים** — שורת צ'יפים מעל טופס ההוספה, עם הפריטים שאתם קונים הכי הרבה ועדיין לא ברשימה. לחיצה מוסיפה מיד.
- **השלמה אוטומטית** — הקלדה בשדה השם מציעה מוצרים מתוך בסיס הנתונים (`products-db.js`), וממלאת אוטומטית קטגוריה ומחיר משוער.
- **תקציב משוער** — סכום כולל (₪) מוצג ליד סרגל ההתקדמות.
- **הוספה ממתכון** — כפתור 📖 בכותרת. מדביקים רשימת רכיבים (שורה לרכיב), האפליקציה מזהה כמות ומשייכת לקטגוריה, ואתם מאשרים לפני הוספה.
- **סטטיסטיקה** — כפתור 📊 מציג את 10 המוצרים שנקנים הכי הרבה, לפי היסטוריית קניות אמיתית.
- **היסטוריית קניות** — "נקו פריטים שנקנו" מעביר פריטים לארכיון (`history`) במקום למחוק אותם סתם — משם ניזונות גם הסטטיסטיקה וגם "פריטים מהירים".
- **מצב אופליין** — Firestore persistent cache מאפשר להוסיף פריטים גם בלי אינטרנט בסופר, והסנכרון קורה כשהרשת חוזרת.

## הקמה (פרויקט Firebase: groceries-b1f9f)

1. ודאו ש-Firestore Database קיים (Build → Firestore Database → Create database, אם עדיין לא).
2. ב-Rules הדביקו (מכסה items, history, meta, templates ו-receipts):
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /items/{itemId} { allow read, write: if true; }
       match /history/{docId} { allow read, write: if true; }
       match /meta/{docId} { allow read, write: if true; }
       match /templates/{docId} { allow read, write: if true; }
       match /receipts/{docId} { allow read, write: if true; }
     }
   }
   ```
   ולחצו **Publish**.
3. פרטי ה-Firebase כבר מוזנים בתוך `app.js`.

## פריסה ל-GitHub Pages

1. ריפו, למשל `yosetre-eng/Shopping-list`.
2. העלו: `index.html`, `app.js`, `products-db.js`, `manifest.json`, `sw.js`, `README.md`. (`carrefour_scraper.py` לא צריך להעלות — הוא רץ אצלכם במחשב, לא באתר.)
3. Settings → Pages → Deploy from branch → `main` / root.
4. הוספה למסך הבית מהדפדפן להתקנה כ-PWA.

## מחירי קרפור — מה עשיתי ומה לא

לא הצלחתי לסרוק את כל קטלוג קרפור אוטומטית מפה: `carrefour.co.il` הוא אתר שנטען לגמרי ב-JavaScript (SPA), אין תוכן קבוע לקרוא בלי דפדפן אמיתי שמריץ אותו. גם אם הייתי יכול — אלפי מוצרים עם מחירים ומבצעים שמשתנים כל הזמן, כך שקובץ סטטי היה מתיישן תוך ימים.

מה שכן עשיתי: `products-db.js` מכיל כ-90 מוצרי סופר נפוצים עם **מחירים משוערים** (לא scrape חי, מסומן בבירור בראש הקובץ) — מספיק לתקציב גס ולזיהוי קטגוריה אוטומטי.

כדי לקבל שמות ומחירים **מדויקים בדיוק כמו בקרפור**, כדי שאגם תזהה בדיוק את המוצר שהבאת: צירפתי `carrefour_scraper.py` — סקריפט Python+Playwright שאתה מריץ אצלך. הוא דורש שתפתח את carrefour.co.il ב-DevTools ותמצא את שמות ה-class הנכונים (מוסבר בראש הקובץ), כי אלה עלולים להשתנות בעדכוני אתר. אחרי הרצה הוא מייצא `products-db.generated.js` באותו פורמט בדיוק — מחליפים בו את `products-db.js`.

## קיצור iOS Shortcuts — הוספת פריט בלי לפתוח את האפליקציה

בדומה לקיצורים שבנית למזגן: שולחים פריט ישירות ל-Firestore, בלי Cloud Function, כי הכללים פתוחים לכתיבה.

1. **Ask for Input** (Text) — "מה חסר?"
2. **Format Date** (Current Date) — ISO 8601
3. **Get Contents of URL**:
   - URL: `https://firestore.googleapis.com/v1/projects/groceries-b1f9f/databases/(default)/documents/items`
   - Method: `POST`
   - Headers: `Content-Type: application/json`
   - Request Body (JSON):
     ```json
     {
       "fields": {
         "name": { "stringValue": "[Provided Input]" },
         "category": { "stringValue": "other" },
         "done": { "booleanValue": false },
         "addedBy": { "stringValue": "יוסף" },
         "createdAt": { "timestampValue": "[Formatted Date]" },
         "qty": { "integerValue": "1" }
       }
     }
     ```
     (מחליפים את הסוגריים המרובעים במשתני Shortcuts המתאימים.)
4. **Show Notification** — "נוסף לרשימה 🛒"

אפשר להוסיף למסך הבית או ל-Siri ("תוסיף לרשימה"). קטגוריה תמיד תהיה "שונות" בדרך הזו (אין השלמה אוטומטית מחוץ לאפליקציה) — אפשר לתקן בתוך האפליקציה אחר כך.

## פיצ'רים לחווית קנייה בפועל (הסיבוב האחרון)

- **🚶 מצב קנייה** (כפתור בכותרת) — מסתיר את טופס ההוספה, מציג רק פריטים פתוחים, קטגוריות שהושלמו נעלמות אוטומטית (במקום לגלול), פונט וכפתורים גדולים יותר, סרגל ההתקדמות נדבק לראש המסך. בסיום — הודעת "סיימתם 🎉".
- **גלגל+ צף (FAB)** למטה בפינה במצב קנייה — הוספת פריט מהירה בלי לצאת ממצב קנייה.
- **מסך דולק (Wake Lock)** — כשמצב קנייה פעיל, המסך לא נכבה אוטומטית (נתמך בדפדפנים תומכי Wake Lock API — כרום/אדג' בטוח, ספארי מ-iOS 17.4 ואילך).
- **החלקה (swipe) על פריט** — ימינה מסמן כ"נקנה", שמאלה מוחק (עם אפשרות "בטל" בהודעה למטה). לחיצה ארוכה (כחצי שנייה) מסמנת "⚠ חסר בסניף" בלי למחוק — שימושי כשמשהו אזל בסופר ואתם רוצים לזכור לחפש תחליף.
- **קיפול קטגוריות** — לחיצה על כותרת קטגוריה מכווצת/פותחת אותה. המצב נשמר מקומית בטלפון.
- **חלוקת קטגוריות בין השניים** — תג "👤" ליד כל קטגוריה, לחיצה עליו עוברת בין "לא משויך" ⟶ יוסף ⟶ אגם. כפתור 👁/👤 בכותרת עובר בין "הצג הכל" ל"הצג שלי" (מציג רק קטגוריות שהוקצו לך או שלא הוקצו לאף אחד). זה סטטי וידני — לא מעקב מיקום, בהתאם לבקשה.
- **הוספה בקול (🎤)** — אם הדפדפן תומך (כרום בעיקר), לוחצים ומדברים בעברית והשם מתמלא אוטומטית.
- **ביטול מחיקה** — מחיקת פריט (בין אם ב-✕ ובין אם ב-swipe) מציגה הודעה עם כפתור "בטל" למשך 5 שניות.

## חיסכון בזמן בהוספת פריטים (הסיבוב הזה)

- **סטפר כמות (−/+)** במקום הקלדת מספר.
- **תבניות קניות (🗂)** — שומרים את הרשימה הפתוחה הנוכחית בתור תבנית בשם חופשי (למשל "קניות שבוע"), וטוענים אותה בלחיצה אחת בפעם הבאה. משותף לשניכם.
- **סריקת ברקוד (📷)**, אם הדפדפן תומך (כרום/אדג' בעיקר — לא ספארי): פותח מצלמה, מזהה ברקוד EAN/UPC, ומחפש את שם המוצר במאגר הציבורי [Open Food Facts](https://world.openfoodfacts.org) וממלא אוטומטית. שימו לב: הכיסוי של מוצרים ישראליים שם חלקי — לפעמים לא ימצא, ואז פשוט מזינים ידנית.

## 📸 סריקת קבלות (תמונה או PDF) והשוואת מחירים

לוחצים על 📸 בכותרת, ובוחרים: תמונה (צילום/גלריה) **או קובץ PDF** של קבלה דיגיטלית (כמו קבלות שמגיעות במייל מרשתות כמו שופרסל/רמי לוי אונליין). האפליקציה:

1. **PDF**: מנסה קודם לחלץ את שכבת הטקסט האמיתית מתוך הקובץ (מדויק כמעט ב-100%, כי זה טקסט דיגיטלי אמיתי ולא זיהוי תמונה). אם ה-PDF הוא בעצם תמונה סרוקה בלי שכבת טקסט (קורה בקבלות שצולמו וממופו ל-PDF), עוברת אוטומטית לזיהוי טקסט (OCR) על העמוד הראשון.
2. **תמונה**: מריצה זיהוי טקסט (OCR) ישירות, **על המכשיר עצמו** — לא שולחת שום דבר לשרת חיצוני (Tesseract.js, קוד פתוח, נטען מ-CDN בפעם הראשונה).
3. מנתחת את הטקסט: שם חנות, פריטים עם מחיר, וסכום כולל.
4. מציגה תצוגה מקדימה **ניתנת לעריכה** לפני שמירה.
5. שומרת ב-collection נפרד `receipts` (לא נוגעת ברשימת הקניות הפעילה).

**עכשיו זה גם משפיע על הסטטיסטיקה:** הפריטים מכל קבלה שסרקתם (תמונה או PDF) נספרים גם בטאב "הכי נקנה" בתוך 📊, לצד מה שכבר נוקה מהרשימה הפעילה — כך שהסטטיסטיקה משקפת גם קניות שלא עברו דרך האפליקציה מלכתחילה (למשל קנייה ספונטנית שרק סרקתם את הקבלה שלה בדיעבד). וגם ב"פריטים מהירים" מעל טופס ההוספה.

**השוואת מחירים** (טאב שני בתוך 📊): לכל מוצר שסרקתם ביותר מחנות אחת, מוצג מחיר בכל חנות, עם הזול ביותר מודגש בירוק.

### חשוב לדעת (כנות לגבי מגבלות)
- **PDF דיגיטלי עם טקסט אמיתי = הכי מדויק.** אם יש לכם אפשרות לקבל קבלה כ-PDF (למשל מקנייה אונליין), זו הדרך הכי אמינה — עדיפה משמעותית על צילום.
- **זיהוי טקסט מתמונה (OCR) לא מושלם** — נייר תרמי דהוי, קמט, זווית עקומה, פורמט שונה בכל רשת. **בגלל זה יש תמיד תצוגה מקדימה לעריכה**, אף פעם לא שמירה אוטומטית.
- PDF עם כמה עמודים: כרגע רק העמוד הראשון עובר OCR אם צריך (רלוונטי רק ל-PDF סרוק בלי שכבת טקסט; PDF עם טקסט אמיתי - כל העמודים נקראים).
- ריצה ראשונה איטית יותר (טעינת ספריות מ-CDN), אחר כך מהיר כי הדפדפן שומר בקאש.
- לא הטמעתי API בתשלום (כמו Google Vision) — זה נשאר חינמי לגמרי ורץ מקומית. שדרוג לדיוק גבוה יותר ידרוש שרת backend, לא אפשרי מ-GitHub Pages בלבד (מפתחות API לא יכולים לשבת בקוד גלוי לכולם).
